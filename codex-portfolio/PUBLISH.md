# Размещение v29 на GitHub для сравнения

## Рекомендуемый вариант: отдельная папка в текущем репозитории

1. Откройте репозиторий `portfolio` и его опубликованную ветку/папку. Источник публикации указан в Settings → Pages.
2. Внутри опубликованной папки создайте новую папку `preview-v29-fixed`.
3. Загрузите в неё СОДЕРЖИМОЕ `daria-github-pages-v29-fixed-mobile`: `index.html`, CSS, JS и папки `assets`, `vendor`. Файл `index.html` должен лежать непосредственно в `preview-v29-fixed`.
4. Сохраните изменения и дождитесь завершения публикации GitHub Pages.
5. Откройте: https://webdesignwithdaria.github.io/portfolio/preview-v29-fixed/

Главная страница и любые предыдущие preview-папки останутся доступны. Не заменяйте их файлы. Настройку источника GitHub Pages менять не нужно: новая версия — вложенная страница существующего сайта. Если сайт публикуется через GitHub Actions, добавьте папку именно в каталог, который workflow отправляет в Pages.

На телефоне/планшете сравните начало видео, момент появления первого проекта и дальнейшее чтение описания. Проверяйте на одинаковой ширине окна. На экранах шире 1024 px эта версия выглядит как v28.

## Альтернатива: новый репозиторий

Создайте, например, `portfolio-v29-fixed`. Загрузите СОДЕРЖИМОЕ этой папки в корень репозитория. В Settings → Pages выберите Deploy from a branch → `main` → `/(root)`.

Адрес при таком имени репозитория:
https://webdesignwithdaria.github.io/portfolio-v29-fixed/

## Важно при загрузке

- Распакуйте ZIP перед загрузкой: GitHub Pages не распаковывает его автоматически.
- Сохраните структуру `assets/` и `vendor/`.
- Включите пустой файл `.nojekyll` (на Mac скрытые файлы отображаются через Command+Shift+.).
- Все пути относительные, поэтому сайт работает и в корне репозитория, и в preview-папке.
- Никакие npm-команды или сборка не нужны.

Справка GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
