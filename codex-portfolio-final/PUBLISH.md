# Как опубликовать v30, сравнить версии и подключить субдомен

## 1. Сначала — отдельная страница

Новый репозиторий не нужен. В архиве находится папка `codex-portfolio-v30`.

1. Распакуйте ZIP на компьютере.
2. Откройте существующий репозиторий `webdesignwithdaria/portfolio` на GitHub, вкладку Code, его корневую папку.
3. Нажмите Add file → Upload files.
4. Перетащите целиком папку `codex-portfolio-v30`. Не сам ZIP и не отдельно её содержимое: на этом шаге нужна вложенная папка.
5. Убедитесь, что среди загружаемых путей есть `codex-portfolio-v30/index.html` и `codex-portfolio-v30/assets/head-occlusion.svg`.
6. В первом поле Commit changes напишите, например, `Add portfolio v30`. Это описание изменения; оно не задаёт адрес страницы.
7. Выберите Commit directly to the main branch и нажмите Commit changes.
8. Дождитесь успешного запуска Pages в разделе Actions. Если ваш Pages публикуется из другой ветки или `/docs`, загрузите папку именно в этот источник, указанный в Settings → Pages.

При существующем источнике `main / (root)` адрес новой версии:

https://webdesignwithdaria.github.io/portfolio/codex-portfolio-v30/

Прежняя главная остаётся по адресу:

https://webdesignwithdaria.github.io/portfolio/

Предыдущая дополнительная страница остаётся по адресу:

https://webdesignwithdaria.github.io/portfolio/codex-portfolio/

Если новая страница даёт 404, сначала проверьте завершение публикации и путь: внутри `codex-portfolio-v30` должен сразу лежать `index.html`, без второй папки с тем же именем.

## 2. Если версия не подходит

Оставьте текущую главную. Загрузка v30 в отдельную папку её не заменяет. Подключать субдомен до выбора версии не требуется.

## 3. Если v30 понравилась и вы хотите сделать её главной

Для текущей структуры репозитория главную определяет `index.html` в корне опубликованного сайта. Одного переименования коммита или изменения DNS недостаточно.

1. Сохраните резервную копию текущего репозитория: Code → Download ZIP. Также запишите ссылку на последний коммит перед заменой.
2. Внутри локальной папки `codex-portfolio-v30` выберите файлы сайта: `index.html`, `style.css`, `app.js`, `idle-loop.js`, `projects-data.js`, `text-motion.js`, папки `assets`, `vendor` и `.nojekyll` (если файл скрыт, на Mac его показывает Cmd+Shift+.).
3. В GitHub откройте корень источника публикации и загрузите туда это **содержимое** через Add file → Upload files. Здесь уже не переносите внешнюю папку `codex-portfolio-v30`.
4. Подтвердите замену одноимённых файлов коммитом, например `Make v30 the homepage`. Существующие папки сравнения оставьте. Если в корне уже есть файл `CNAME`, сохраните его.
5. После публикации откройте `https://webdesignwithdaria.github.io/portfolio/` и проверьте страницу.

Чтобы вернуть прежнюю главную после замены, восстановите её файлы сайта из резервной копии в тот же корень. Можно также отменить коммит замены с помощью Git. Папки сравнения для этого удалять не нужно.

## 4. Подключение субдомена через GoDaddy

Пример: ваш существующий домен — `example.com`, желаемый адрес портфолио — `portfolio.example.com`. Замените `example.com` своим доменом. Субдомен создаётся DNS-записью, отдельно покупать его не нужно.

Сначала GitHub:

1. В репозитории `portfolio` откройте Settings → Pages.
2. В Custom domain введите `portfolio.example.com`, без `https://` и без пути, затем Save.

Затем GoDaddy (если DNS домена обслуживает GoDaddy):

1. Откройте Domain Portfolio → ваш домен → DNS.
2. Выберите Add New Record → CNAME.
3. Заполните:

| Поле | Значение |
|---|---|
| Type | CNAME |
| Name / Host | `portfolio` |
| Value / Points to | `webdesignwithdaria.github.io` |
| TTL | значение по умолчанию |

4. Сохраните запись. Если имя `portfolio` уже занято DNS-записью, сначала выясните, что к нему подключено. Если DNS обслуживается другим провайдером, создайте запись там.
5. После успешной DNS-проверки в GitHub Pages включите Enforce HTTPS, когда переключатель станет доступен. Обновление DNS и выпуск сертификата могут занять время.

В CNAME нельзя писать `/portfolio/` или `/codex-portfolio-v30/`: DNS указывает на хост, а не на папку. После замены главной и подключения субдомена новая версия будет открываться прямо на `https://portfolio.example.com/`. Настройка относится ко всему Pages-сайту этого репозитория; папки сравнения останутся вложенными страницами.

Для этого шага нужны изменения только выбранного субдомена. Записи основного сайта и почты, включая `@`, `www` и MX, оставьте как есть.

Официальные инструкции, проверены 23 октября 2026:

- [GitHub: custom domain и поддомен](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)
- [GoDaddy: добавление CNAME](https://www.godaddy.com/help/add-a-cname-record-19236)
